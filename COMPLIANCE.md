## goodpractice findings and justified exceptions

- **Function length / cyclomatic complexity:** remaining long routines include
  numerical kernels, plotting setup and input validation. Shared fitting,
  plotting, fold, mapping, permutation and residual helpers reduce duplicated
  work. The largest complexity scores are `envfit.coca` (33), `simpls` (26),
  `permutation_matrix` (23), `validate_count` (22), and `make_mapper` (16).
  Compound validation predicates contribute strongly to these scores. Further
  extraction should improve a coherent operation rather than merely lower a
  metric; these are tracked maintenance opportunities, not all resolved flags.
- **Unused internals:** `mcLin` and `scaleLin` are retained legacy helpers with
  direct numerical tests. They are currently unused by the public fitting path;
  removing them offers little benefit and may disrupt existing internal users.
- **Coverage:** the threshold is exceeded, but goodpractice asks for 100%.
  Remaining lines are redundant legacy guards in `coinertia.default`, progress
  messages and contextual error handlers, nonfinite-statistic/fold-error guards,
  a malformed-block guard, and the residual-inertia roundoff warning. Every
  retained function executes; unforced floating-point warning paths remain.
- **Depends:** vegan remains attached for compatibility with users who call its
  generics after attaching cocorresp. Moving it to Imports requires a separate
  deprecation/compatibility decision.
- **Line length:** some mathematical roxygen, references and legacy comments
  exceed 80 columns. Air formats executable code; focused lint excludes cosmetic
  line length, naming and formatting rules that conflict with legacy APIs/Air.
- **Missing arguments:** `lapply(..., \`[\`, , choices)` deliberately selects all
  rows. Existing dimension-dropping semantics of loadings are retained.
- **paste:** the flagged call collapses species names with `collapse = ", "`;
  it is intentional and does not construct paths.
- **Single-argument c():** two retained public default expressions use
  `c(1:min(...))`. They are redundant, but preserving the exact defaults avoids
  an unnecessary interface change.
- **Test expectations:** numerical outputs intentionally use `expect_equal`
  with tolerances. Class-vector equality is explicitly tested with
  `expect_identical`, which is stronger than merely testing class membership.
- **Unavailable roxygen checks (four):** goodpractice's static preparation fails
  resolving the dataset topic `beetles`; direct roxygen generation and package
  documentation checks succeed. Do not rewrite valid data topics to satisfy
  this tool incompatibility.
- **Unavailable URL checks (two):** goodpractice passes a `fail` argument no
  longer accepted by installed urlchecker. Direct `urlchecker::url_check()`
  succeeds and provides the replacement evidence.

The final queried CRAN index listed no reverse dependencies. This is a point-in-
time result, not a guarantee about GitHub/private users. Repeat before release.

## Performance and publication gates

`benchmarks/parallel.R` records repeated serial and reused-worker timing plus
startup overhead. On the local machine, two-worker PSOCK startup was about
0.15 seconds; median beetles LOO times were 0.13 seconds serial / 0.08 seconds
parallel, and permutation times 0.25 / 0.12 seconds. These small measurements
are illustrative, machine/load-dependent and not a general speedup claim.
Serial remains the default; reuse clusters for repeated calls.

The following remain release gates, not completed external operations:

- Run the configured Windows/Linux/macOS, R 4.1, oldrel and devel jobs on GitHub.
  Local validation covers only the stated macOS/R version. Review dependency
  resolution on the minimum supported R before declaring that matrix supported.
- Review the complete site visually in a browser and confirm live deployment.
  Automated site checks and local PNG inspection passed; browser page preview
  was blocked by the local browser URL policy. No remote workflow was triggered.
- Remove legacy tracked site files from the source branch only after the new
  deployment is verified, as required by RELEASE-CHECKLIST.md.
- Obtain human review of the scientific changes, documentation and snapshots;
  record it in AI-USAGE.md. No human review is implied by automated checks.
- Collect research-use evidence and differentiation, obtain a release DOI, and
  recheck current JOSS submission requirements before preparing the paper.
